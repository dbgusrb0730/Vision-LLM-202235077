# 코드 설명 순서

## 먼저 설명할 전체 흐름

이 프로그램에는 두 흐름이 있습니다.

1. `main.py`가 카메라 영상을 읽고 `vision.py`에서 사람과 관절을 찾습니다. `framing.py`가 구도를 판정하고, 조건이 유지되면 사진을 저장합니다.
2. `assistant_worker.py`가 별도 스레드에서 음성을 받고 안내합니다. `audio_io.py`는 Whisper/Piper를 실행하고, `commands.py`는 명령을 동작으로 바꾸며, `gemma.py`는 구도 설명과 자유로운 문자 명령 해석을 담당합니다.

별도 스레드가 필요한 이유는 Gemma 응답이나 음성 합성을 기다리는 동안에도 카메라 화면을 갱신하기 위해서입니다.

## 파일별 설명

| 파일 | 설명할 핵심 |
|---|---|
| `main.py` | 프로그램 시작, 카메라 반복 처리, 명령 적용, 화면 표시, 사진 저장, 종료 |
| `vision.py` | YOLO로 사람 수와 박스를 얻고 MediaPipe로 33개 관절을 얻음 |
| `framing.py` | 전신/상반신 기준 판정과 촬영 대기·카운트다운·취소 관리 |
| `commands.py` | 하나→전신, 둘→상반신, 사진→재촬영 등 명확한 명령 변환 |
| `assistant_worker.py` | 음성과 Gemma 처리, 메인 루프와 메시지 교환 |
| `audio_io.py` | 녹음 → Whisper 한국어 인식 / Piper 합성 → 재생 |
| `gemma.py` | GGUF 모델을 CPU로 로드하고 관측 정보를 프롬프트로 전달 |
| `settings.py` | 설정 파일을 읽고 모델 경로·값을 검사 |

### main.py

- `main()`: 실행 옵션을 읽고 준비 상태를 확인한 뒤 `run()`을 실행합니다.
- `run()`: 매 프레임 `observe → assess → gate.update → 화면/저장`을 반복합니다.
- `terminal_input()`: 터미널 입력을 음성 명령과 같은 처리 경로로 보냅니다.
- `Overlay`: OpenCV의 기본 글꼴 대신 Pillow로 한글 안내를 그립니다.
- `save_photo()`: 안내가 그려지지 않은 원본 프레임과 촬영 정보를 저장합니다.
- `finally`: 정상 종료나 오류 모두에서 카메라와 관절 인식기를 정리합니다.

`argparse`는 AI 기능이 아니라 실행 명령 뒤에 붙은 옵션을 읽는 표준 도구입니다. 기존 실행 방법을 유지하려고 실제 사용한 옵션을 남겼습니다.

| 옵션 | 필요한 이유 |
|---|---|
| `--config` | 노트북과 Jetson의 모델·장치 경로 선택 |
| `--vision-only` | 노트북 음성이 불안정할 때 카메라와 촬영만 확인 |
| `--text-only` | 음성 대신 터미널로 Gemma 연결 확인 |
| `--check` | 강의실에서 실행 전 누락된 파일·패키지 확인 |
| `--audio-devices` | 실제 마이크와 스피커 번호 확인 |

### vision.py와 framing.py

`Vision.observe()`는 원본 영상을 분석용 크기로 줄이고 사람을 검출합니다. 사람이 정확히 한 명일 때 관절을 찾습니다. 좌표를 영상 너비·높이로 나눠 0~1 범위로 표현하므로 해상도가 달라도 같은 기준을 쓸 수 있습니다.

`Observation`은 사람 수·박스·관절, `Landmark`는 관절 좌표와 신뢰도, `Advice`는 판정 코드·안내 문장·촬영 가능 여부를 묶는 자료형입니다. `dataclass`는 이 값들을 저장하는 클래스를 간단하게 선언하는 방법입니다.

`assess()`는 사람 수, 관절 가시성, 여백, 중심, 크기를 순서대로 확인하고 우선 해결할 문제 하나를 반환합니다. 전신은 얼굴·어깨·골반을 확인하고 발이 잘려도 허용합니다. 상반신은 얼굴·양쪽 어깨만 확인하는 클로즈업 모드입니다. 같은 관절 목록을 움직임 검사에도 사용하므로 화면 밖의 발이나 허리 추정치가 흔들려도 촬영을 막지 않습니다. 구도 기준값은 초기 시연용 경험적 기준입니다.

`CaptureGate`는 아래 흐름을 관리합니다.

```text
모드 선택 → 촬영 대기 → 구도 0.5초 안정 → 4초 카운트다운 → 한 장 저장 → 대기 해제
                                  ↘ 움직임/미검출 발생 → 안정 확인부터 다시 시작
```

`signature()`는 박스와 주요 관절 좌표를 모읍니다. `anchor`는 안정 확인을 시작한 기준 위치입니다. 매 프레임을 이 기준과 비교하므로 천천히 계속 움직이는 것도 감지합니다. `time.monotonic()`은 시계 시간이 조정돼도 경과 시간을 안정적으로 계산하기 위해 사용합니다.

### assistant_worker.py와 commands.py

- `requests`: 메인 루프에서 전달한 터미널 명령·음성 출력 요청.
- `events`: 음성 스레드가 전달하는 모드 변경·인식 문장·오류 등.
- `snapshot`: 메인 루프가 알려 주는 최신 구도 상태.
- `lock`: 두 스레드가 구도 상태를 읽고 쓰는 순간을 보호합니다.
- `busy`: 음성 인식·설명·일반 안내 중에는 촬영 안정 시간을 다시 쌓도록 알립니다.
- `stop_event`: 종료를 알립니다.
- `revision`: 모드 변경이나 취소 뒤에 이전 구도 설명을 재생하지 않도록 구분합니다.

짧고 명확한 명령은 `direct_intent()`가 바로 처리합니다. 잘못 인식된 음성을 Gemma가 촬영 명령으로 추측하지 않도록, 목록 밖의 음성은 재발화를 요청합니다. 터미널의 자유 문장은 Gemma로 해석할 수 있습니다.

### audio_io.py와 gemma.py

노트북은 sounddevice, Jetson은 수업의 arecord/aplay를 사용합니다. 두 경로는 실제 실행 환경이 달라 유지해야 합니다. Whisper와 Piper는 `subprocess`로 기존 실행 도구를 호출합니다. 임시 WAV는 `TemporaryDirectory` 안에 만들고 사용 후 정리합니다.

카운트다운 숫자는 시작할 때 미리 합성하여 촬영 중 매번 합성하느라 지연되지 않게 합니다. 안내 재생 중에는 마이크를 듣지 않아 자신의 안내를 사용자 명령으로 오인하는 일을 줄입니다. 녹음 프로세스 중단 코드는 취소·종료 후에도 마이크를 계속 점유하지 않도록 필요합니다.

`GemmaDirector.complete()`는 로컬 모델에 프롬프트를 보내는 공통 부분입니다. `intent()`는 터미널 문장을 명령으로 분류하고, `explain()`은 이미 계산된 구도 판정을 한국어로 설명합니다. Gemma에 사진 자체를 보내지 않으므로 이미지용 mmproj는 필요하지 않습니다.

## 설치·검사 파일의 역할

`prepare_models.py`는 초기 모델 준비용, `check_gemma.py`는 모델 연결 검사, `test_director.py`는 동작이 바뀌지 않았는지 확인하는 자동 검사입니다. 이 세 파일은 일반 촬영 중 실행되지 않습니다. 설명할 때 실제 촬영 코드와 설치·검증 코드를 구분하면 됩니다.

이번 정리에서는 미사용 변수·import, 사용하지 않는 mmproj 다운로드 옵션, 항상 같은 값으로 호출하던 생성 길이 인자, 중복 취소 처리를 제거했습니다. 구도 임계값·명령·모델 경로·음성 녹음 방식·촬영 시간은 바꾸지 않았습니다.
